# ADR-0008 — Target Revit 2025, not 2026

- **Status:** accepted
- **Date:** 2026-09-21
- **Supersedes:** the Revit-version assumption in ADR-0001

## Context

Revit 2026 (26.1.0.35) was installed first and pyRevit 6.5.5 attached to
it cleanly. Automated launch nevertheless failed every time:

- `pyrevit run` hung for exactly 300 s on `manage licensing`, then
  `LicenseUpd(1) Adlsdk Error:(20) vendor:ADLM`
- `adlm-err.log`: `VendorError=-8` against `licpath.lic`
- the pyRevit add-in never loaded — Revit died before reaching it

Two theories were tested and both were wrong:

1. *A second Revit session held the licence* — the failure recurred with
   no Revit running, and the journal then read "**Primary** Revit session
   detected", not secondary.
2. *Sign-in had never completed* — the Autodesk identity caches were all
   absent and the licence record was empty, which looked conclusive. But
   **AutoCAD's licence record was equally empty** while AutoCAD ran
   headlessly all day. So an empty record does not mean unlicensed.

Revit 2025 (25.0.2.419) was then attached and tested. It **worked first
time**: 17 s, exit 0, full Revit API access, and a signed-in
`revit_username` — while a Revit instance was open, which also disproves
theory 1 independently.

Also noted: the 2026 install sits at `C:\Program Files\Revit 2026\`,
outside the usual `Autodesk\` root, and the error log shows two different
`licpath.lic` paths across attempts — consistent with a reinstall having
left it in an inconsistent state.

## Decision

Target **Revit 2025** for all automation. Keep 2026 installed but do not
depend on it.

## Consequences

- The Revit automation path is unblocked and verified end to end:
  a model built with known dimensions extracts to exactly the right
  wall lengths and room area, in millimetres.
- `docs/SETUP.md` instructs a fresh machine to start from 2025.
- The extract has no 2026-specific API calls, so moving forward is a
  configuration change, not a rewrite.

## Resolved (2026-09-22)

**The root cause is now known: the client's Autodesk entitlement covers
Revit 2025 only.** There is no 2026 licence. The 300 s hang and
`Adlsdk Error:(20)` were an unlicensed product failing slowly, not a
defect to diagnose.

That retires the investigation above. The two disproved theories were
still worth disproving — they were the plausible ones — but the answer
was simpler than any of them, and it is a reminder to ask what the
client actually owns before profiling a licence failure.

Consequence, and it is the expensive one: **Revit 2026's content library
is unusable.** 3,237 metric families sit on the disk under
`C:\ProgramData\Autodesk\RVT 2026\Libraries`, while 2025 has 446, almost
all annotation and structural — no doors, windows, furniture or light
fixtures. Revit families are **forward-compatible only**, so 2026 content
cannot be loaded into a 2025 project even though it is right there.

The 2025 content library is therefore a separate ~2 GB download from the
client's Autodesk Account (All Products and Services → Revit → View
Details → Libraries), taking the **UK/International English** metric
packages rather than US Imperial.
