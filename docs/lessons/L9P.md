# L9P lessons (defect -> why it was missed -> guard)

| defect | why it was missed | guard now |
|---|---|---|
| 5 of 17 room-chosen cameras stood in a door opening and the render faced the closed door leaf (n08, n15, n17, plus two more). | My resolver copied the intent API of `villa_render._VIEWS` but not its `reframed = "doorway"` rule, so the build never hid the leaf. Nothing in `villa_render_views.py` checks "a view is mostly one flat door". | `render_set.resolve` sets `reframed` by the same rule; `test_room_views_at_room_edge_or_in_an_opening_are_doorway_views` (fails on the old resolver: 5 views). Open: a pixel guard for "one hue/one texture fills more than 60 % of the frame". |
| A new view inventory cannot use `knowledge/exposure-groups.json`: `require_record` binds it to the exact view list and every camera. Each camera fix forced a 6-11 min GPU re-measure. | `write()` has a fixed record path; the record is part of the scene's identity (by design, RA 2026-11-21). I learned it from the traceback, not from a doc. | `render_set.write_scene(record=...)` takes the record path; the set's record lives in `knowledge/render-set/exposure-groups.json`. Rule for any camera work: finish the camera set on plan (`villa_render_views.py`, `render_set.coverage`) before measuring; measure once. |
| Editing any file under `src/archpipe/` while a scene build ran aborted the build ("source changed during build"). | The provenance hash covers every `src/archpipe/**/*.py`, my lane's critic code included. | Documented here; builds run to completion before any src edit. |
| The room chooser returns cameras that are legal and useless: a pantry shot of a bare end wall, a lobby shot of a flat wall, a library nook shot from inside facing joinery. | The chooser's score is "subjects in frame, clear of walls"; no term for what else is in frame. | Authored standing points in `knowledge/render-set/views.json` (n04, n05, n10, n18, n19) with `covers` checked on plan. Open: a "dominant flat surface" score in `render_views.choose` (L6d). |
| A "windowless" corridor (n10) came out strongly blue. | The exposure rule put it in `lamp-dominant` (65 % lamp light) and applied that group's 2700 K white balance while 35 % of its light is cool daylight. | Not fixed here (exposure rule is not our file). Reported with the numbers (owner: lead/L6d). The critic's R12 is expected to catch it; the extension table says whether it did. |
