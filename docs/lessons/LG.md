# LG lessons (defect -> why it was missed -> guard)

| defect | why it was missed | guard now |
|---|---|---|
| A pond-edge sensor behind the east-yard bench read 0.8 lx (the plane's "minimum" demanded 9.9x the light of every other point). | The ring was the pond rect grown by 0.6 m and clipped to paving; nobody stands on the 0.24 m strip between a bench and the wall, but the grid sampled it. The first run reported a product failure that was a sensor-placement fault. | `garden._walkable`: floor sensors are taken only where a person can stand (furniture footprints removed, then a 0.15 m morphological opening drops slivers under 0.30 m). `tests/lightcalc/test_garden.py::test_ring_excludes_slivers_and_furniture` (the strip is empty), `v3_sensors` (no sensor within 50 mm of an object; negative: one in a bench). |
| The first glare check failed every scene at 33 000 - 56 000 cd/m2. | The sightline of the stock LA4 check was aimed AT each fitting, so a fitting always fell inside its own 45 deg cone: a pass was impossible (a property of the sightline, the same family as the L6d bed finding, in reverse). | `check_glare` uses level sightlines to what people look at (table, fire pit, door, pond) from every seat; negative `test_negative_fitting_aimed_at_the_seat_fails`. The real finding it then made was kept: a downlight 1.1 m beyond the table, tilted at the diners, read 33 000 cd/m2 -> the dining fittings are now over the table and aimed straight down. |
| LA4 said "not_evaluated" for every sightline that saw an uplight. | The generic IES carries a zero luminous opening, and `luminance_toward` refuses a zero area; the aggregate looked like a pass because only `fail` statuses were counted. | The aggregate passes only if EVERY sightline is `pass`; the ASSUMED uplight file carries a 60 mm opening. `test_design_passes_in_every_scene` (a not_evaluated fails it). |
| `check_la12` failed the install at ULR 1.00 (every uplight). | ULR is defined for the luminaire in its installed attitude, so an uplight is 1.0 by construction; the E3 limit (0.15) is meant for light that reaches the sky, and a tree crown stops it. | `sky_escape`: rays of the uplight that miss the opaque (leaf-on) crown ellipsoid; the check is on that fraction (worst 12 % for the east-yard olive, the smallest crown), the raw 1.00 is reported beside it. `test_negative_uplight_missing_its_crown_fails_ulr`, `test_uplight_aimed_into_its_crown_is_caught_by_the_crown`. The crown is assumed opaque in leaf; in winter the crape is bare, so the winter scene switches the uplights off. |
| The Radiance cross-check disagreed with the analytic engine by 3.4 % on the fire-pit ring. | My test restricted the Radiance job to two zones but compared it with analytic light from ALL zones; individually every fitting agrees to 0.02 % (single-fitting probe, tilted and vertical, every aim). | `radiance_check` compares the same fixtures on both sides; the direct agreement is 0.02-0.05 % on the planes. Lesson kept for a debug order: compare ONE fitting at a time before blaming the engine. |
| "Do not flood the water" (rule text) had no check; the first design lit the water as brightly as the margin (86 % of the ring mean at a 12 % output). | LS-POND-EDGE-LIGHT is a margin rule; its fix text carries a prohibition nobody had turned into a number. | `check_water` (policy: water mean <= margin mean, card `LG-POLICY-pond-water-not-flooded`) with a negative. The Iku, a downlight, cannot do better than ~0.85: reported as a limit, not tuned away. |
| 12 % output on every pond zone at night, where 7 % already meets 8 lx. | The product (676 lm) is oversized for a margin task: 100+ lx at full output on 8 lx of need. | `solve_levels` reports the minimum level per plane and V12 headroom (all four safety zones need 4-11 % of output, far under 80 %); the scene levels are never below the floor (`test_scene_levels_never_below_the_safety_floor_when_the_zone_is_in_use`). A smaller product would be a better buy; none with a 2700 K file exists (see docs/lanes/LG.md). |
| The John Cullen Kew 25 file (a converter's IES) made LA4 say "not_evaluated" and `ies2rad` stop with "illegal source dimensions" for the Radiance cross-check. | The header writes its 16 mm round opening as width 0 / length -0.016 (the LDT says 16 mm round); the engine's circular rule needed both fields and the Radiance writer only took absolute values. The old uplight and the ERCO file wrote both fields. | `luminous_area_m2` and `radiance_safe_ies` give a one-field diameter to both fields (tests `test_kew_opening_is_read_from_its_file...`, `test_radiance_safe_ies_gives_a_one_field_diameter_to_both_fields`, on the real file). |
| With the real uplight file, glare would have failed 3-5 x over the policy cap (10 275 / 15 412 cd/m2, UP-3) had the head been treated as a bare opening. | The ASSUMED file had a cosine-power beam with zero light at the horizon; a real file has a small back lobe, and the luminance of a 16 mm opening seen at a grazing angle is large by definition. | The Kew is declared `shielded` from its datasheet wording; `test_kew_opening_is_read_from_its_file_and_its_shield_is_what_keeps_glare_in_policy` fails the bare case, so the exception cannot be dropped or widened silently. |
| The first V10 of the Kew medium file failed lumens by 0.25 point and the Kona's beam diameter by 5-6 %. | Neither had been run before binding (the assumed file could not fail). | Reported in `candidates.json` and the lane doc; `test_v1_inputs` pins the Kew's -2.25 % so a swap of the file is noticed. |
