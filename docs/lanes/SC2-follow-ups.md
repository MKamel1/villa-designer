## 1. Understair cupboard depth

* **Steel in the model?** No. The wall-stringer bearings (16), wall plate, open-side stringer and glass shoe existed only in
  `villa_render.py` (labels "ASSUMED ...; add to Revit"); `stair-main` carried treads and riser infill, nothing else. That is
  invented geometry, so it is now model data: `model/stair_steel.py` (offsets, one source for the scene builder and the model),
  `stair-main.params.steel` (19 members with the scene mesh ids, y extents, basis ASSUMED pending an engineer, plus
  `wall_side_y_mm` -28396 and `open_side_y_mm` -27536).
* **Diagnosis.** Spec cupboard y -28.471..-27.471 (1000 mm); steel leaves y -28.396..-27.536 (860 mm). The spec box crossed the
  steel on both faces (75 mm at the bearings, 65 mm at the shoe/glass).
* **Fix.** The joinery yields: `spec_source._yield_to_steel` sets the model cupboard back face to the bearing face and the
  side wall's outer face to the shoe face. Model: 3096 x **860** mm (was 1000), interior y -28.396..-27.636, volume **2.21 m3**
  (was 2.62; SC measured about 2.2 on the built carcass), side wall and door y -27.586. The scene builder already drew exactly
  this (`G1.understair_cupboard` from the steel planes); `test_model_footprint_equals_what_the_scene_builder_draws` ties them.
* **Evidence (RV1 on the same IFC).** K10: 50 pass / 3 fail -> **51 / 2** (`joinery-understair-cupboard` clears; the two left are
  `furn-lounge-tv` and `furn-study-tv`, 12 mm short, unchanged). The furniture schedule row (3096 x 860) was regenerated by
  `python -m archpipe.documents`.

## 2. `wall-B-ext-16` and the window head

* **Diagnosis.** `wall-B-ext-16` 2650 mm, `wall-B-ext-17` 2800 mm, `slab-roof-0` soffit 2800 mm above the B floor. Cause:
  `revit_spec._parking` gave every B cross wall `min(WALL_H, P.clear_at(x))`, and `clear_at` beyond the deck's end (x 12.777)
  still returns the deck's 2.65 m although the extension roof there is `slab-roof-0` (soffit 2.80 m).
* **Fix.** `revit_spec._soffit_clear`: beyond the deck end, with a roof beyond the deck, the clear height is `WALL_H` (2.80).
  The post-condition `clearance_problems` uses the same rule for cross walls. Only `walls[16]` changes in the specification.
* **Window heads found** (model, all 8 windows): the B storey holds one window, `window-B-dirty-kitchen-0` (sill 0, height 2300,
  head 2300 mm, `full_height`); the 7 GF windows have head 2300 mm (sills 900/1700). **2.30 m is the one standard head; kept.**
* **K06 after:** still 1 fail, `window-B-dirty-kitchen-0`: glass 0 -> 2300, **500 mm** below the soffit, 150 mm allowed.
  Reading: the 500 mm is now wholly an ordinary wall header (the 150 mm open slot is gone, the wall meets the 2.80 m soffit).
  Not retuned. Same D07 class as SC reported (a window marked full height, glazed to the standard head); a design decision.
* **Open (same cause, not changed):** the south B wall, one piece x 6.877..15.412 at 2650 mm, runs 2.635 m beyond the deck end
  under the 2800 mm roof: a 150 mm slot. Splitting it at x 12.777 renumbers every later `wall-*` id (ids are list indices), so
  it was left for a decision. `clearance_problems` keeps the deck soffit for walls along the ramp for that reason (stated in a comment).
* **Consequence handled.** The approved hood-canopy host face (`c4-e-lead-approvals.json` row
  `host-face-support-appliance-hood-dirty-canopy`) takes the wall's height: top -0.35 -> -0.20 (the same value as its sibling rows).
  The movement (13 mm in y) is unchanged. See "Ownership exceptions".

## 3. RV1 K09 reads `scene["element_contract"]`

`parity.checks.k09_identity(w, model, contract)`: an id listed in `light_only` or `imported_props` is not "built 0 times"
**if the model holds it**; a listed id the model does not hold fails; an element missing from the scene and not listed
still fails. `run_d1` and the mutation set pass the contract. Tests (`tests/parity/test_checks.py`): listed light-only id
passes; unlisted still fails; no contract = old behaviour; entry naming no model element fails.

`-tree-south`: the model ids are `plant-landscape-*`, the benches are scene-only), so `element_contract` now lists props under
the id the model holds and puts scene-only props in `non_model_props`.
**K09: 0 / 45 / 8 -> 1 / 0 / 8** (pass/fail/not evaluated; the 8 are the informational `nonmodel-*` classes). Recall 40/40
(same rows); mutations 39, 36 caught, the same three documented misses (M1, M6-180, M-K10-move0.1): nothing dropped.
